# Holly Share source review

Reviewed 2026-10-19 at [commit 3fcf772273d6f3db3423b2eb39f5db70ee601519](https://github.com/titleunknown/holly-share/tree/3fcf772273d6f3db3423b2eb39f5db70ee601519). This is a static review of the downloaded source and official MediaMTX documentation. No project scripts were run, dependencies installed, live settings changed, or transmitter/browser behavior tested.

Holly Share turns a Mac into a local viewing relay for a Hollyland Pyro H. The author says the transmitter accepts one RTSP connection; the Mac takes that connection and distributes it to nearby viewers. Viewers join the same reachable network and scan a QR code to watch in a browser. The stated dependencies are MediaMTX, FFmpeg, and qrencode, installed through Homebrew. [Project explanation and requirements](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/README.md#L3-L20)

The useful design choice is to copy H.264 video and convert only the audio to Opus for WebRTC. The original feed remains available for RTSP, RTMP, and HLS. The generated HTML is a local QR display; the browser playback URLs point at MediaMTX. [Pipeline](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L228-L256), [local page launch](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L341-L357)

My assessment: a useful small utility with a sensible media pipeline. I would improve operational safety and visibility before adding more streaming features.

1. **Restrict publishing first.** The generated config supplies no authentication rules and leaves `live` at path defaults. Under the author's tested MediaMTX 1.21 defaults, anonymous network clients have publish/read permissions, publisher replacement is enabled, and the RTSP listener accepts connections on all interfaces. Together these imply that another reachable client can replace the browser feed's publisher. This is a configuration finding, not a reproduced attack. Keep publishing and API access local, grant viewers read access only, and offer a session password or revocable viewing token. Preserve the existing loopback API binding. [Holly Share config](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L236-L250), [MediaMTX 1.21 permissions](https://github.com/bluenviron/mediamtx/blob/v1.21.0/mediamtx.yml#L49-L85), [RTSP binding](https://github.com/bluenviron/mediamtx/blob/v1.21.0/mediamtx.yml#L228-L242), [publisher default](https://github.com/bluenviron/mediamtx/blob/v1.21.0/mediamtx.yml#L440-L467), [replacement default](https://github.com/bluenviron/mediamtx/blob/v1.21.0/mediamtx.yml#L558-L561)

2. **Own and stop only this session's processes.** Shutdown currently force-kills every process whose command line matches the local publish URL. It also lacks an `EXIT` cleanup handler. Replace that with tracked process ownership, graceful shutdown followed by a bounded force-stop, and cleanup on every exit. Add a single-instance lock or unique run directory. The fixed temporary directory otherwise allows simultaneous launches to overwrite each other's runtime files. [Runtime directory](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L232-L236), [launch and shutdown](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L295-L313), [final wait](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L354-L357)

3. **Make networking explicit.** Address selection is a heuristic, and `--share-ip` changes displayed URLs without setting listener bindings or ICE configuration. Offer a named choice of transmitter connection and viewer network, validate reachability, and refresh URLs after address changes. Include an actual WebRTC connectivity check. A reachable HTTP page does not prove the media channel works. MediaMTX uses a separate ICE connection, defaults to UDP 8189, and needs additional configuration for TCP fallback or TURN. [Address selection](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L206-L256), [upstream WebRTC defaults](https://github.com/bluenviron/mediamtx/blob/v1.21.0/mediamtx.yml#L373-L391), [official connectivity guidance](https://mediamtx.org/docs/features/webrtc-specific-features#solving-webrtc-connectivity-issues)

4. **Show continuous health.** Replace the one-time startup check and terminal-only workflow with a small status window showing source online/offline, viewer count, audio availability, recent errors, and reconnecting state. Give viewers a clear disconnected screen and automatic fallback when practical. The script checks readiness during startup and then waits on MediaMTX; its QR template has no ongoing health display. [Startup readiness](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L315-L328), [run loop](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L330-L357), [QR template](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/share-page.html#L37-L54)

5. **Measure the supported envelope.** Publish a tested browser/device table, end-to-end delay, sustained viewer counts, and recovery results after Wi-Fi interruption and transmitter restart. Test both hotspot-only and Mac-to-wired-LAN arrangements. The author lists one transmitter and Apple Silicon macOS test setup, describes hotspot capacity as a few viewers, and labels Tailscale untested. Video passthrough is efficient, but compatibility still depends on the source codec/profile; MediaMTX specifically warns that H.264 B-frames fail in browser WebRTC. [Author's network guidance](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/README.md#L42-L70), [tested setup](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/README.md#L127-L133), [official codec limitations](https://mediamtx.org/docs/features/webrtc-specific-features#codec-support-in-browsers)

6. **Package and generalize after those fixes.** A signed Mac menu-bar app could expose Start/Stop, network choice, diagnostics, and QR export without Terminal or manual configuration editing. Keep the current media pipeline underneath. Record supported dependency versions, check them before startup, and add failure-path integration tests. For wider camera support, accept a complete RTSP URL and saved device profiles; changing only the port still assumes the fixed `/live` path. [Current installer](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/Install.command#L16-L31), [configuration fields](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L62-L89), [fixed source path and detection](https://github.com/titleunknown/holly-share/blob/3fcf772273d6f3db3423b2eb39f5db70ee601519/holly-share.sh#L182-L204)

The security findings depend on MediaMTX 1.21 defaults and assume no external environment overrides or network access controls. The reported single-connection transmitter behavior, hotspot bandwidth, and tested-device claims come from the author. Static review does not establish real-world latency, image quality, viewer capacity, or recovery reliability.
