## Blocking findings (most serious first)

**B1. The operator's Capture Frame fails at normal outgoing sizes (chat).** `SessionModel.swift:944-949` saves the full-size outgoing picture as a JPEG at quality 0.7. Display sharing can send up to 3840×2160 (`MacScreenCapture.swift:34-37`). The frame check in `SessionChat.swift:81-86` refuses anything wider or taller than 1920 pixels, over 2.07 megapixels, or over 128 KB, before it shrinks the picture. A 1080p screen at quality 0.7 is usually well over 128 KB. So on most real feeds the operator gets "Capture a new JPEG frame from the feed", and capturing again fails the same way. The gateway test passes only because its frame is 64 pixels square. The capture also runs on the main thread.
- Fix: shrink to at most 1280 pixels, off the main thread, and lower the quality step by step until it fits under the limit. Do the same in the server's re-encode (fixed at 0.65 in `SessionChat.swift:92`), because re-encoding a busy 960-pixel viewer frame can push it back over 128 KB.
- Add a test using a detailed 1920×1080 or 3840×2160 frame.

**B2. Opening the app can still show nothing (app reopening).**
- `openMonitor` is set only in `MainView.onAppear` (`MainView.swift:88-91`), and `model.launch()` also runs only there.
- If the app starts without its main window ever appearing (for example, quit with that window closed and the system restores that state), `openMonitor` is nil, `monitorWindow` is nil, and `reopenMonitor()` only activates the app. That leaves the menu-bar-only state Austin reported. S-016 explicitly requires "Cold launch presents the main scene".
- `AppReopenTests` uses a plain NSWindow, so it says nothing about the real main window being closed and then reopened.
- Fix: keep a way to open the main window that doesn't depend on MainView having appeared, make sure the main window is shown on a cold launch (`.defaultLaunchBehavior(.presented)` on macOS 15 or later, with a fallback for 14), and don't make the model's startup depend on that window.
- Evidence needed on the native app:
  - Close the main window with the red button, then open the app from the Dock, from Finder (`open -a`), and from Spotlight, both with the Join Codes window or floating preview visible and with no window.
  - Minimize the main window, then open the app.
  - Quit with the main window closed, then start it cold.
  - Each time, show exactly one main window and check that sharing did not start.

**B3. Picking a secured Wi-Fi network creates an open-network code (Wi-Fi).** `SharingPanel.swift:263` clears the password when a name is picked, and `passwordFormat` (`ViewingWiFiBrowser.swift:69`) then shows "Open network. No password is included in its join code." The browser already knows `network.open`. If the operator saves at that point, phones get an open-network QR code for a WPA network and fail to join. That breaks the S-015 rule that a missing password never produces an open-network code.
- Fix: pass the network's security type into the draft. For a secured network, say "This network needs a password", and block or confirm before saving with no password.

**B4. Chat has no moderation, and image origin is overstated (chat).**
- Any admitted viewer can post any JPEG with a hand-made request; the server only cleans it up. It cannot tell whether it is a feed frame.
- The UI still labels it "Shared feed frame" (`chat.js:73`, `SessionChatView.swift:51`).
- The operator cannot delete a message or image, and removing a viewer leaves their messages in place. The only way to remove content is Stop, which ends the session for everyone.
- Fix: add an operator-only Remove Message action that drops the stored image too (and optionally lets the operator remove a viewer's messages along with the viewer), and label images by sender ("Image from Sam"), not as feed frames.

**B5. A source switch leaves frame capture open (chat).** `setAudienceHold` turns frame permission off immediately (`SessionModel.swift:889`). The source-switch path (`SessionModel.swift:714-717`) starts a Hold transition but never calls `gateway.setChatFramePermission(false)`. Until `replaceSource` finishes and the state is published again, the gateway still reports Live with permission on and the old revision number. A viewer can therefore post the outgoing source's last frames while the operator is switching away, and they stay in chat afterwards. Close the gate when the switch begins, as Hold already does.

## Should fix (not blocking)

- **Operator chat performance.** `SessionChatView.swift:49` takes the gateway lock and decodes every stored image each time the view redraws. The view watches the whole model, which republishes `lastFrameAt` on every snapshot. With 8 images that means repeated JPEG decoding on the main thread. Cache the decoded images by message ID when the message list changes.
- **Unread indicators.** Neither side shows new messages: viewers only check while chat is open (`chat.js` `poll` runs only when open), and the operator has no badge on the Chat tab or the menu bar. So the "Digi can reply" exchange depends on someone happening to have chat open. A count in the existing heartbeat response for admitted viewers would avoid a public event stream.
- **Shared rate limit.** Likes and posts share one 0.5-second limit (`SessionChat.swift:66-71`). Liking then sending quickly shows "Wait a moment".
- **Dead reply target.** Once the original message drops out of history, the reply target stays set on both sides and every retry fails until Cancel Reply. Clear it automatically.
- **Duplicate operator label.** The default operator name "DigiTech" plus the "DigiTech" role tag reads "DigiTech DigiTech". A viewer can also simply call themselves "DigiTech". Use a visual operator badge rather than text.
- **Join codes export.** Print has no check that sharing changed after the dialog (Save has one). Export also ignores the Both / Feed / Wi-Fi choice and is blocked entirely when only the Wi-Fi password is unavailable, even if just the feed code is wanted.
- **Menu bar "Open Setbeam"** (`SetbeamApp.swift:97`) calls `openWindow` directly instead of `reopenMonitor()`, so a minimized main window won't come back.
- **Shortcut order.** In the Sharing menu, Chat is ⌘4 but sits between Viewers (⌘2) and Options (⌘3), while the tabs run Invite, Viewers, Chat, Options.
- **`docs/status.md`** has no changes since the snapshot. AGENTS.md requires recording evidence and remaining work there.
