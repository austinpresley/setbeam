# Setbeam 0.2.0 build 20

October 29, 2026. Apple Silicon, macOS 14 or later. Developer prerelease, ad-hoc signed and not notarized.

## Changes since October 21, 2026

This covers changes dated October 21–29, from the build 9 repository cleanup through build 20. [Compare the source](https://github.com/austinpresley/setbeam/compare/c8e91d896c4fb1e81b13ebe3a093967faada7cee...v0.2.0-build20).

### Sources and local monitoring

- **This Mac's screen** is a source. Choose a display by name and resolution. Capture includes the cursor, excludes Setbeam windows, and has no sound. It requires Screen Recording permission.
- Connected displays have rounded, updating thumbnails in the source chooser. The currently monitored display reuses its existing feed.
- **Hollyland Pyro H** discovery is ported into the native chooser. It checks the current Wi-Fi router for a compatible H.264 `/live` stream on ports 5554, 554, and 8554 without opening a media reader. Selection uses the existing single-receive RTSP pipeline. Physical Pyro H testing remains pending.
- Network sources retain their received H.264/HEVC encoding for local monitoring. Browser viewers use a separate H.264 encode. Capture inputs use their active size and cadence.
- Native preview uses timestamped video and audio with bounded queues. Main and floating windows display pictures through GPU-backed pixel buffers. The floating preview keeps zoom and pan.
- A visible live picture keeps the Mac display awake. Private session logs record recovery and audience events without credentials or viewing links.

### Sharing and browser viewing

- The browser viewer has a larger picture, a compact feed/status strip, and icon controls. It fits the decoded aspect ratio without cropping.
- Live, Hold, reconnecting, blocked playback, and ended sessions have distinct states. Full screen, keyboard shortcuts, connection help, browser picture-in-picture where available, and phone keep-awake where supported are included.
- Viewers may supply an optional name. The operator sees opened versus playing sessions and observational playback health, with struggling viewers shown first. These readings do not promise a fixed end-to-end latency.
- Viewer frame rate and picture quality are independent. Choose 1, 5, 10, 15, 24, 25, or 30 fps, or match the source up to 30 fps. Quality offers 12, 6, or 3 Mbps per viewer. Dimensions stay unchanged at lower frame rates.
- Mac screen capture has its own remembered frame-rate choice. Relaunch still restores private monitoring, with sharing and Hold off.
- Join codes can stay open beside the picture. Loopback-only viewing now offers a viewing-network action instead of an unusable invitation for other devices.
- **Picture settings** has a dedicated sheet. Intentional Hold uses blue; recovery uses amber. Hold removes source picture and sound from outgoing media while local monitoring continues. Stop sharing also leaves local monitoring running.

### Stability and recovery

- Detailed 4K pictures no longer overflow the old relay reader queue. Native playback recovers its clock after late frames, and oversized screen keyframes trigger a bounded encoder restart.
- Native GPU presentation reduced measured CPU use in the virtual-display 4K check from 202% to 26%. This measurement is specific to that local test.
- All Setbeam encodes are capped at 30 fps. Incoming external-source monitoring retains its received cadence.
- Low-frame-rate viewer encoding now respects its bitrate allowance, including 4K at 1 fps. Large-keyframe integration coverage was added.
- Replaced-source playback requests no longer interrupt viewer recovery. Ended/expired links have a self-contained generic page, and Hold/Stop leave browser picture-in-picture.
- The runtime owns source replacement and incoming RTMP session state. Recovery retains sharing intent, Hold, and the viewing credential where supported.
- Optional automatic Wi-Fi rejoin targets the saved transmitter network after loss. It is off by default, requires macOS Location access, and avoids switching Wi-Fi while viewers depend on it. A physical automatic-rejoin qualification remains open.

### Repository and delivery

- The source repository keeps the original Holly Share launcher and MIT attribution under `docs/upstream/`.
- The GitHub introduction, setup guide, current screenshots, and downloadable app now describe build 20.
- Runtime dependencies and their notices/source archives ship with the app. No developer Homebrew installation is required to run it.

## Validation and limits

The local release check results, artifact hashes, screenshot provenance, and packaging audits are recorded in [publication verification](../verification-release-build20-2026-10-29.md). All validation runs locally; GitHub Actions remains disabled.

Physical wireless evidence remains limited to the recorded CineView Master 4K firmware 3.30 unit and its tested 1080p60 computer-display route. The newer monitoring path still needs a physical recheck. Pyro H has simulated software evidence only. Other transmitters and physical capture devices remain unqualified.

Long-session reliability, audible native Mac sound and A/V timing, physical 4K displays and phones, broader Safari/VoiceOver coverage, Intel builds, older macOS versions, Developer ID signing, and notarization remain open. The recorded 120-second hardware soak failed its continuous criterion with 2 unavailable samples out of 116; the two-hour run remains deferred. See [hardware tests](../hardware-tests.md) and [current status](../status.md).
