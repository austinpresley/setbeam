# Setbeam 0.2.0 build 40

November 11, 2026. Apple Silicon, macOS 14 or later. Developer prerelease,
ad-hoc signed and not notarized.

[Download the Mac app](https://github.com/austinpresley/setbeam/releases/download/v0.2.0-build40/Setbeam-0.2.0-build40-macOS-arm64.zip)
· [Installation and setup](../getting-started.md)

## Memory and viewer access fixes

- Fixes the sustained memory growth affecting display and application-window
  sharing in public build 20. Drained video-pipe storage is released, and native
  previews enforce a shared buffer ceiling across rendering and recovery.
- Approved viewers stay listed when their page stops sending updates. No recent
  update marks unconfirmed playback, and Remove stays available. New requests
  cannot silently evict an approved viewer when the session table is full.
- Enabling approval suppresses the previous shared output while permissions are
  applied. If a credential or reader-disconnect update fails, sharing ends and
  the viewing link is retired. Your private monitor continues. Start sharing
  again to retry with the current permissions.

## Changes since public build 20

- Share one application window, with an updating source preview, instead of the
  entire display. Screen and window capture remain video-only.
- Optional viewer approval, individual admission/removal, chosen names and colors,
  playback health, shared pointers and pointers on this Mac's shared display.
- A readable local address and an optional ask-only short address. Every
  short-address request requires explicit operator admission.
- Session chat with replies, emoji reactions and explicitly captured outgoing
  frames. The operator can remove a message for everyone. Chat uses local HTTP,
  is not encrypted, and clears at Stop. New frame attachments are blocked during
  Hold; already sent images remain in the conversation.
- A restrained floating preview, clearer recovery instructions, visible outgoing
  picture/audio status and separate joined/playing counts.
- Sharing can sit beside the monitor or in its own window. Join codes can float,
  save to PDF or print. Viewing Wi-Fi details include password-format feedback;
  actual password validation still requires a phone joining that network.
- More compact phone chat and controls, saved option drafts, and reliable app
  reopening from Finder or the Dock.

## Validation and limits

The complete local packaged check passes 303 Swift tests with one opt-in
endurance soak skipped, 59 Node checks, five Python cases and all media stages.
Actual Chrome viewers confirm stale-session removal, continuity for the other
viewer and Hold/Resume/Stop. Light/dark native checks, eight Chrome and seven
macOS WebKit layouts pass. The accelerated writer check sends 79.35 GiB with
0 MiB reported footprint growth. See the [verification record](../verification-release-build40.md)
for fault injection, earlier failed/interrupted attempts and qualification limits.
No hosted test, build or packaging workflow is used.

This remains a developer prerelease. The recorded CineView Master 4K firmware
3.30, 1080p60 computer-display route is the only physically tested wireless
route. Pyro H has simulated software evidence only. Camera content, physical
capture devices, broader phone/Safari coverage, native audible output and A/V
timing, the deferred two-hour hardware run, physical 4K devices, older macOS,
Intel builds, Developer ID signing and notarization remain unqualified. See
[hardware tests](../hardware-tests.md) and [current status](../status.md).
